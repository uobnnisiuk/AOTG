# AOTG 高速化技術リサーチ・トラッカー

> **独立したオフライン静的Webアプリ。** GitHubへソースを保存しても、サイト公開・自動同期・実機への適用は行われません。

## GitHub内の配置・再生成

- `index.html` — そのままブラウザで開ける配布用ファイル（シードデータ内包）。
- `template.html` — 画面・スタイル・JavaScriptの原本。シードの代わりに `__SEED_JSON__` を持ちます。
- `seed.json` — 調査ID・出典・数値の初期レコード。既存のSPD IDとREF/LOC区分を維持します。
- `build.py` — 標準ライブラリのみで上記2つから `index.html` を再生成するスクリプト。

```sh
python docs/research-tracker/build.py --check
python docs/research-tracker/build.py
```

`seed.json`を更新する場合は、出典・根拠段階・欠測・反証を確認し、既存IDの重複を避けてから再生成してください。ブラウザの編集内容はGitHubに自動同期されません。必要ならJSONをエクスポートしてレビュー済みのPRとして取り込みます。**GitHub Pagesの有効化・Sites公開は別作業**です。

**公開安全基準:** 認証情報、内部IP、個人情報、業務コード、個人環境の非公開構成値、秘密鍵・モデル重みをこの公開ディレクトリへ登録しないでください。環境別の測定メモ `LOC-001/002` は原ログ・ハッシュ未照合であり、研究・採用済みの性能結果ではありません。

作成日: 2026-11-18（JST）

## 利用方法

1. `index.html` をブラウザで開きます。外部CDN・サーバー・APIキーは不要です。
2. 「技術カタログ」で検索、分類・根拠・環境の絞り込み、詳細・編集・新規登録を行えます。
3. 「比較・検証」で技術を2件並べ、公開値／既存計測メモ、品質、メモリ、安定性を比較できます。メトリクスの単位や試験条件が異なる場合、速度倍率は自動計算しません。
4. 「調査ワークフロー」で継続調査の手順・次の確認作業・希望頻度案を管理します。希望頻度は**未指定**で、選択しても承認待ちの提案になるだけです。
5. 「承認待ち」は外部書込み・実機検証・変更・タスク設定を未承認のまま明示します。
6. 「参照・データ」からJSON・CSVをエクスポートできます。JSONをインポートすると、同じIDまたは同じ名称・出典のレコードを統合します。ブラウザの保存領域に依存しないよう、JSONバックアップを推奨します。

## 新規調査 → 既存カード更新の手順

1. 上流一次資料のPR、commit、Release、論文、作者技術ノートを確認します。
2. SPD ID、手法名、原理、コミット、出典URLで#34と照合し、重複は同じ記録へ追加します。
3. `bottleneck`、`mechanism`、対象段階、ハードウェア・driver・模型・quant・context・batch・warmup・試行数を保存します。
4. `metrics`は`公表値`／`既存計測メモ`／`第三者再現`／`当方実機検証`を区別して記録し、品質と長文、VRAM/RAM、swap停止、安定性、反証・不採用理由も保存します。
5. 実行や設定の変更は別の承認事項とし、情報収集の作業からは自動実行しません。
6. 情報に実質的な差分がある場合だけ更新します。頻度は未指定です。既存の別タスク（日次12:00 JST）は変更していません。

## 制約

- **Sitesへの登録・公開は実施していません。** このファイルは移植可能な静的HTML版です。
- オンライン同期、サーバーDB、複数端末共有、定期自動実行は含みません。
- Browser `localStorage` への編集保存は、ブラウザ・ファイルURLの取扱いによって利用できない場合があります。必ずJSONでバックアップしてください。
- 実機ベンチ、SSH、モデル起動、GitHub/Linearへの投稿・修正、機器・OS・ドライバの設定変更、承認・予約・課金・CI/PR/mergeは行いません。
- 初期数値は元資料の文脈とリンクしていますが、すべての個別資料の現在の最新コミットや性能を再実測したものではありません。現場への採否判断には独立試験が必要です。

## 2026-11-22｜独立レビュー指摘の限定修復

- 旧版の27件をブラウザに保存している場合も、手動変更したID・個別の監査ログを保ち、新しい内蔵seedの未登録13 IDだけを追補します。保存済みの同一IDを暗黙に上書きしません。
- 技術名だけの編集では測定値のbefore／after／noteと未知の追加フィールドを保持します。指標の名称・単位・出所・条件が重複なく一致する限り、行の順序変更と値の編集を組み合わせても原記録の追加フィールドを正しい指標に保持します。行の追加・削除も別の指標へ根拠を転記しません。同一性が曖昧な変更（名称等の変更と別行削除／追加の同時操作や識別キー重複）は保存前に拒否します。編集前にJSONバックアップを取ってください。
- JSON取込では全件の文字列・配列・metric形状・重複IDを事前検査し、失敗時はブラウザのstate／保存領域を一切変更しません。正常時だけ一括反映し監査記録を追加します。
- CSVの数式開始文字とその前の空白・制御文字を無害化します。通常の日本語と数値はそのままです。出力先ソフト固有の扱いは別途確認してください。
- 日付は初期登録日と内蔵seedの収録照合日を区別します。編集内容はGitHub/Linearへ同期されません。
