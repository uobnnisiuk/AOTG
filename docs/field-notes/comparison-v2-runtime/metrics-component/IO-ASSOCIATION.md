# Offline I/O association checks

`tools/io_capture_diagnostics.py` validates collected evidence for the reviewed I/O v2 producer. It does not start the producer, import its source, discover files, or inspect a live process. The caller must pin this helper before importing it and obtain the input inventory from an independent, externally trusted assessment record.

Call `io_capture_diagnostics(reader, descriptors, expected)`. `reader.raw(path, maximum)` must safely read an immutable, bounded regular file from the independently trusted collection. Each descriptor has exactly `path` and raw `sha256`. Collection paths may differ from the logical original paths inside the plans.

Required descriptor roles are `lifecycle_source`, `sampler_source`, `wrapper_source`, `native_helper_source`, `plan`, `client_plan`, `worker_plan`, `authorization`, and `job_plan`. Optional emitted roles are `launch`, `first_sample`, `samples`, `job_receipt`, `stderr`, `cancel`, and `lifecycle_result`. Omit missing evidence instead of manufacturing a success record. The four producer source hashes are fixed in the helper; a source revision requires a new reviewed helper.

`expected` has exactly these keys: `run_id`, `nonce`, `authorization_sha256`, `client_plan_sha256`, `client_plan_raw_sha256`, `worker_plan_sha256`, and `plan_sha256`. The authorization and first client hash are canonical JSON hashes; the latter client hash, worker hash, and I/O plan hash bind raw bytes. Derive run/client/worker identities from the independently verified assessment inputs. Obtain the authorization hash and I/O plan descriptor from the independent authority and its reviewed record. Do not accept a generated file as its own trust authority.

The checks join the full existing SSH route, source hashes, launch command digest, stream header and every row, first-sample receipt, native Windows job receipt, terminal result, and raw file inventory. Limits are 6,257 records, 8,192 bytes per JSONL line, and 32 MiB of sample output. Invalid foundational identities or hashes raise `IOCaptureError`; missing or invalid emitted records return `status: incomplete` with fixed reason codes. Output contains hashes and safe diagnostics, not commands, paths, payloads, or raw errors.

`associated_terminal_complete` means these records consistently describe the configured sampler deadline and a completed Windows wrapper under the external trust assumption. It does not prove that all workload intervals are covered. The sample-count test deliberately accepts a terminal association with a large observation gap so coverage cannot be mistaken for provenance. Evaluate actual coverage and counter-derived rates separately against the identical `input_sha256.samples` bytes.

A cancellation, missing final, invalid receipt, missing terminal, reported lifecycle error, or unresolved cleanup cannot produce terminal completion. A valid cancelled run may still establish `owned_windows_job_cleanup_verified`. That field covers the Windows job object and exited wrapper only. `remote_process_exit_verified` is always false; neither JobEmpty nor the sampler final proves the state of every remote descendant. Quality, adoption, rates, and coverage remain unevaluated. These are consistency checks, not cryptographic authentication of the operator or producer process.

Validation: 23 synthetic tests passed locally. They read the four reviewed producer files as inert bytes. They do not start SSH, the sampler, native Windows helpers, services, or inference. No new host run, approval, or deployment is implied.
