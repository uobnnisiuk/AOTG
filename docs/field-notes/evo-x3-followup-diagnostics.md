## Passive observation

The owner-private capture ran from 02:45:16 to 02:45:40 UTC: 13 samples over about
24 seconds. All `pswpout` readings were106, all `pswpin` readings6 and all
`oom_kill` readings0. Memory PSI cumulative totals, major faults, direct/kswapd
scan counters and the captured allocation-stall counters did not increase.
The minimum `MemAvailable` was59,787,603,968 bytes (55.68GiB). Global swap usage
was417,792 bytes throughout. The original service state matched before and after;
the SSH job ended successfully and its Windows job was empty.

The failed startup's15 accepted samples were48. The later value106 establishes
only a later observation. The rejected startup value, when the difference arose,
and which activity caused it remain unknown. This capture does not prove that a
future model load is free of swapout. It provides no reason to weaken the existing
zero-increase stop rule or change swappiness, swap, cache or OS settings.

All visible per-process `VmSwap` values were0 in the before/after scans. This is
not the same metric as global swap use: the kernel documents that `VmSwap`
excludes shared-memory swap. `MemAvailable` is an estimate that includes
reclaimable memory. Neither metric proves that a particular allocation will not
trigger reclaim. See the [kernel proc documentation](https://docs.kernel.org/filesystems/proc.html).
The observed swappiness value60 is an IO-cost policy, not a RAM percentage
threshold; see the [kernel VM documentation](https://kernel.org/doc/html/latest/admin-guide/sysctl/vm.html).
No shared-memory or process-level cause is asserted from these facts.

The original collector has a timestamp limitation: its sample end/elapsed fields
are evaluated before the vmstat/meminfo reads, and its final UTC precedes the
service/process scan. Independent review recorded this explicitly. The raw records
are retained; they must not be used as strict acquisition-coverage brackets.
A future collector should compute all selected metrics before stamping the end.

## Additive independent grading

The C++ source generated by the earlier real OpenCode task was copied unchanged
and statically reviewed, then compiled and run with the exact PR23 grader/catalog
inside a read-only offline namespace on K8. Real UBSan was available. All15 hidden
assertions passed. This is an additive result: the earlier9-case report and coding
time remain unchanged. No new inference or source repair was performed.

The PR23 independent review also ran24 quality tests and10 isolated synthetic
native cases. Both the actual UBSan path and an actual `-ftrapv` path with only
UBSan-unavailability deliberately injected accepted their reference source and
rejected all four overflow defects. The synthetic checks are grader validation,
not model quality results. Dynamic instrumentation does not prove arbitrary
undefined-behavior absence, and OS shared libraries were not newly pinned.

The [independent review](https://github.com/uobnnisiuk/AOTG/pull/23#pullrequestreview-5914542316)
is anchored to PR23 head`a8be61d6a7ad86dcf22b18563f9426962f1ce7f3`. Its four CI
configurations passed. PR23 is not merged or deployed by this follow-up. Future
runs must pin its new grader and catalog together and create new source-review
receipts; a report bound to the previous catalog cannot be silently reused.
